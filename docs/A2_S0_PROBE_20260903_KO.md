# A2 S0 PROBE — `prev_inner = eigv + 1.0` 이 정확히 무엇을 씨앗으로 놓는가

- 대상 브랜치: `codex/exact-throughput-campaign`
- 선행 문서: `docs/A2_OUTER_REDUCTION_DESIGN_20260902_KO.md` §1.4(a), §3.1 S0/S4, §5 항목 9
- 작성일: 2026-09-03
- 성격: **소스 정독 + 계측 커밋 2건**. 빌드/실행은 181 문법검사만, 계산은 하지 않았다.
- 정확성 어휘: **B0** = 비트 동일, **N1** = 결정론적 궤적 변경(Gate A/B 필요), **A2** = 수용 허용오차 변경.

> **한 줄 결론.** `prev_inner` 는 **직전 아우터의 고유치**이고, 그것이 먹이는 곳은
> **아우터 수렴 판정의 keff 절반, 오직 그것 하나뿐**이다. Wielandt 시프트도 아니고,
> "직전 내부 잔차" 도 아니다. Xe 핸드오프의 `+ 1.0` 은 **이미 올바르게 실려 있던 캐리
> 위에 덮어쓰는 센티널**이며, 그 유일한 효과는 **다음 아우터의 수렴 판정을 구성적으로
> 실패시키는 것**이다. 설계서 §1.4 의 반론(허용오차 산술상 어차피 실패했을 것)은
> **여전히 유효하고 아직 판정되지 않았다** — 이번 커밋이 그것을 판정할 카운터를 붙인다.

## §1. `prev_inner` 는 무엇을 씨앗으로 놓는가 — file:line

### 1.1 소비자는 한 곳뿐이다

`src/Driver.h:4452-4471` (SolveLoop, 호스트 아우터 본문):

```cpp
flux_converged = std::abs(prev_inner - eigv) < keff_tol_now && residual < flux_tol_now;
...
prev_inner     = eigv;
```

`prev_inner` 를 **읽는** 문장은 이 파일 전체에서 여섯 곳이고, **판정에 쓰는 것은 두 곳뿐**이다.

| file:line | 무엇 | 판정인가 |
|---|---|---|
| `src/Driver.h:4452` | SolveLoop 의 `flux_converged` — keff 절반 | **그렇다** |
| `src/Driver.h:2904` | `ReconvergeFlux` 의 같은 판정(`converged`) | **그렇다** |
| `src/Driver.h:4342` | `s.prev_inner = prev_inner` — 디바이스 세그먼트로 업로드 | 위임 |
| `src/Driver.h:2814` | 같은 업로드, `ReconvergeFlux` 쪽 | 위임 |
| `src/Driver.h:4515` | `outertrace::emit` 인자 | 진단뿐 |
| `src/Driver.h:4587` | limit-cycle WARN 의 `|prev_inner − eigv|` | 진단뿐 |

업로드된 값은 `src/CmfdOuterKernel.h:504-505` 에서 같은 두 항으로 같은 판정을 내린 뒤
`st.prev_inner = in.eigv` 로 되돌아온다 — 호스트와 디바이스가 **글자 그대로 같은 식**이다.

### 1.2 세 개의 "아니다"

- **Wielandt 시프트가 아니다.** 그것은 `BICGCMFD` 의 `_eshift`(기본 `0.04`, `src/Driver.h:5407` 의
  `setEshift(0.04)` 단 한 번) 와 그로부터 나오는 `reigvs`(`src/BICGCMFD.cpp` 의
  `1./(eigv + _eshift)`) 다. `prev_inner` 는 CMFD 커널에 **전달되지도 않는다**.
- **"직전 내부 잔차" 가 아니다.** 그것은 `errl2` 이며 `drive()` 가 반환하고 아우터가
  `residual` 로 받는다. `flux_converged` 의 **나머지 절반**은 `residual < flux_tol_now` 이고
  `prev_inner` 와 독립이다. LOOSE 단계가 느슨하게 하는 것도 `flux_tol_now`/`keff_tol_now`
  라는 **문턱**이지 `prev_inner` 라는 **피연산자**가 아니다.
- **내부/외부 수용의 결합점이 아니다.** 내부 예산(`_nmaxbicg`, `_epsl2`)은 `prev_inner` 를
  보지 않는다. 두 분모(설계서 §1.5)는 `residual` 을 통해서만 만난다.

### 1.3 그러므로 `+ 1.0` 이 하는 일은 하나다

아우터는 매번 판정 직후 `prev_inner = eigv` 를 실행한다(`:4471`). 따라서 Xe 스텝이
발화하는 시점에 **`prev_inner` 는 이미 `eigv` 와 같다**. `src/Driver.h:4776` 의

```cpp
prev_inner  = a2_prev_inner_carry ? eigv : eigv + 1.0;   // 기본 = eigv + 1.0
```

는 **올바른 캐리 위에 1.0 을 얹는 것**이고, 다음 아우터에서
`|prev_inner − eigv'| ≈ 1.0 ≫ keff_tol_now` 이므로 `flux_converged` 는 **residual 이
아무리 작아도** 거짓이 된다. 즉 **Xe 스텝 하나당 아우터 바닥이 2**다(스텝을 실은 아우터
+ 수렴이 금지된 아우터 최소 1). 설계서 §1.1 의 실측 2.67 outers/step 과 정합한다.

**"핸드오프 이후 완전 재수렴을 강제하는 센티널인가?" — 부분적으로 그렇다.**
정확히는 **한 아우터를 강제**한다. 그 한 아우터 뒤에는 정상 판정이 복귀하므로
"완전 재수렴 강제" 는 과한 표현이고, "**첫 판정을 무조건 몰수**" 가 정확하다.

### 1.4 같은 관용구의 나머지 세 곳 — 성격이 다르다

| file:line | 자리 | 성격 |
|---|---|---|
| `src/Driver.h:4776` | Xe 캐스케이드 핸드오프 | **XS 가 움직였다.** 재수렴 요구에 물리적 근거가 있다 |
| `src/Driver.h:4798` | interim(느슨한 플럭스) Xe 프로브 | XS 가 움직였고, 애초에 `!flux_converged` 인 자리 |
| `src/Driver.h:4847` | settling gate | **XS 가 움직이지 않았다** |
| `src/Driver.h:4919` | LOOSE→POLISH 전이 | **XS 가 움직이지 않았다** |

디바이스 트윈(`src/CmfdOuterKernel.h:560, :569`)에는 **뒤의 두 자리만** 있다. Xe 핸드오프의
센티널이 디바이스에 없는 이유는 단순하다 — `src/Driver.h:4349-4352` 가
`s.xe_pending = 0; s.th_pending = 0; s.xe_interim_l2 = 0; s.xe_once_mode = 0` 으로
하드와이어하므로 `CmfdOuterKernel.h:551` 의 Xenon 분기는 **도달 불가**이고, Xe 스텝은
언제나 호스트에서 일어난다. **따라서 이번 arm 은 호스트 한 줄로 완결되며 `.cu` 를 열지 않는다.**

## §2. 설계서 §1.4 의 반론은 아직 살아 있다 — 그리고 이제 판정 가능하다

설계서가 스스로 기록한 반론:

> 프로덕션 스테이징에서 cascade 는 `prev_xe_change >= xe_tol_now = 1e-3` 인 동안만 계속된다.
> Xe worth ~2,500–3,000 pcm 에 대해 1e-3 상대 변화는 k 로 ~2.5e-5, 즉 loose keff_tol 5e-6 의
> ~5배다. 따라서 오염이 없었더라도 대다수 스텝에서 수렴 판정은 어차피 실패했을 것이다.

**이 반론은 산술적으로 옳아 보이지만 두 개의 미검증 가정을 깔고 있다.**

1. **Xe worth 로부터 |Δk| 를 유도한 것은 상한이지 실측이 아니다.** `xe_change` 는
   `|new−old|/|new|` 의 **핵종 밀도** 상대 변화이고(`XSSet.cpp` / `XsReconKernel.h`),
   k 로의 전달은 노심 평균 worth 로 스케일한 **한 자리 추정**이다. 캐스케이드 후반
   스텝들은 `xe_change` 가 문턱 바로 위에서 종료되므로 |Δk| 분포의 꼬리가 어디에 있는지는
   추정으로 알 수 없다.
2. **`residual < flux_tol_now` 항이 무시되었다.** 반론은 keff 항만 계산한다. 두 항 모두
   통과해야 수렴이므로, 반론이 옳다면 **hit rate 는 0 에 가까워야 하고**, 그 사실 자체가
   S4 를 죽이는 데 충분하다.

**판정 방법(이번 커밋).** `src/Driver.h:4452` 옆에서, 센티널이 덮어쓴 고유치
`cf_eigv` 에 대해 래더와 **똑같은 두 항**을 한 번 더 평가하고 **버린다**:

```cpp
const bool cf_hit = cf_probe && std::abs(cf_eigv - eigv) < keff_tol_now &&
                    residual < flux_tol_now;
```

읽는 곳은 카운터뿐이므로 digest 불변 = **B0**. 영수증 필드:

```
"counterfactual":{"arm":"sentinel","probed":N,"would_converge":H,"hit_rate":H/N,
                  "probe_coverage":N/xe_step_sentinels,
                  "loose_probed":NL,"loose_would_converge":HL,"loose_hit_rate":HL/NL}
```

- `hit_rate` = 설계서의 `xe_first_outer_would_converge / xe_steps`. **S4 의 킬 기준은
  `< 0.30`.**
- `loose_hit_rate` = **S4 가 실제로 겨냥하는 모집단**(S4 는 `!polishing` 한정).
- `poison_suppressed` / `poison_converged_next` 쌍(설계서 §3.1 S0)은
  `sentinel.{xe_step,settle,polish}` 와 위 두 카운터로 구성된다.

### 2.1 커버리지 — 정직한 한계

프로브는 **호스트 아우터 본문의 판정에 올라탄다.** 디바이스 아우터 세그먼트
(`RASBERY_GPU_OUTER`)가 핸드오프 다음 아우터를 삼키면 세그먼트는 여러 아우터에 대해
판정을 **한 번만** 공표하므로 프로브가 탈 자리가 없다. 그 경우 프로브는 **오귀속 대신
무장 해제**되고(`src/Driver.h` 세그먼트 성공 분기), `probe_coverage` 가 그 사실을 공표한다.

**운용 결론:** S0 계측 런은 `RASBERY_GPU_OUTER=0` 으로 돌린다. 설계서 §4.2 가 이미
계측 런과 타이밍 런의 분리를 요구하므로(m64 는 항상 2회) 이는 새 비용이 아니다.
`probe_coverage < 0.9` 인 런의 `hit_rate` 는 **인용하지 않는다.**

## §3. 반사실 → 수정: `RASBERY_A2_PREV_INNER=carry` (N1 arm)

### 3.1 구현

`src/Driver.h:4084` 에 캐시된 정적 게이트, `src/Driver.h:4776` 에 한 줄:

```cpp
static const bool a2_prev_inner_carry = [] {
    const char* value = std::getenv("RASBERY_A2_PREV_INNER");
    return value != nullptr && std::string(value) == "carry";
}();
...
prev_inner  = a2_prev_inner_carry ? eigv : eigv + 1.0;
```

- **OFF 는 리터럴이다.** 조건 **표현식**이고 본문 접합이 아니다. `71092e2` 선례
  (SolveLoop 에 본문을 접합했더니 인라이닝·`-ffp-contract` 재구성만으로 플래그 OFF digest 가
  `22b9a3187bfb4beb/4566` → `c1a5d9116df9edb3/4601` 로 움직였다)는 **본문**에 관한 것이고
  여기에는 본문이 없다. 별도 TU 불필요.
- **불리언이 아니라 낱말.** `carry` 가 아닌 모든 값은 `sentinel`(오늘의 경로)이다.
  오타는 오늘의 경로에 착지한다.
- **한 자리만.** 나머지 세 센티널은 그대로다. `tools/test_outer_budget_receipt_contract.py`
  가 "무장된 자리는 정확히 첫 번째뿐" 을 단언한다.
- **`trajectory::kArmEnv` 등재.** N1 이므로 case key 를 갈라야 한다 —
  `carry` 로 만든 답이 `sentinel` 요청에 배달되면 안 된다.

### 3.2 영수증 카운터 — "센티널이 더했을 아우터 수"

카운터는 **하나의 쌍**이고 arm 에 따라 **두 가지 읽기**를 갖는다. 그래서 영수증이
`counterfactual.arm` 을 함께 찍는다.

| arm | `would_converge` 의 뜻 |
|---|---|
| `sentinel`(기본) | **반사실** — 센티널이 없었다면 수렴했을 아우터 수 = 센티널이 낭비한 아우터 수 |
| `carry` | **실현치** — 실제로 수렴한 핸드오프 다음 아우터 수 = **센티널이었다면 더했을 아우터 수** |

`carry` arm 에서 `cf_hit` 는 `flux_converged` 와 **항등**이 된다(캐리 후 `prev_inner ==
cf_eigv == eigv_pre`). 즉 같은 식이 한 arm 에서는 예측, 다른 arm 에서는 측정이 된다.
두 arm 의 `would_converge` 가 크게 어긋나면 반사실 모델 자체가 틀린 것이며, 그것도 읽을 수 있다.

### 3.3 예상 효과 — 정직한 밴드

- **상한.** 센티널이 발화하는 Xe 핸드오프 스텝 수(영수증 `sentinel.xe_step`)만큼의 아우터.
  KNGR 프로파일 기준 ~964 스텝 → 런 4,377 아우터의 **~22 %**. 설계서 §1.4(a) 의 "≥42 %"
  는 스텝당 바닥 2 를 **모두** 센티널 탓으로 돌린 수치이고, 그중 **한 아우터만이**
  센티널의 것이다 — **§1.4(a) 의 42 % 는 절반이 과대계상**이다.
- **중심.** 상한 × `hit_rate`. 반론이 옳으면 `hit_rate` ≈ 0.05–0.15 → 런의 **1–3 %**.
  반론이 틀리면 0.4–0.6 → **9–13 %**. **어느 쪽인지는 S0 런 한 번이 답한다.**
- **Gate A 리스크.** N1 이므로 모든 statepoint 의 공표 keff 가 움직인다. 설계서 §3.0 의
  지배 원리대로 `search_tol` = 2e-5 > Gate A 예산 1.905 pcm 인 한 통과 여부는
  **근이 아니라 경로**의 함수다. 따라서 **S1(L0 종단 재수렴) 이전의 `carry` 측정은
  outers/digest 확인용이고, Gate A 판정은 S1 이후로 미룬다.**

## §4. 이번 3커밋이 남긴 것

| 커밋 | 등급 | 내용 |
|---|---|---|
| 1 | B0 | `RASBERY_BICG_NMAX` / `RASBERY_BICG_EPS` → `kArmEnv`(48→50). 서로 다른 내부 예산이 같은 case key 를 공유하던 결함. 영수증 env 라인에 `null` 두 칸이 늘고 **모든 case key 가 한 번 이동**하며, digest 와 outers 는 불변 |
| 2 | B0 | `[RASBERY][OUTER_BUDGET]` 영수증(항상 켜짐). 6-phase 귀속 + cascade 항등식 잔차 + `cmfd_sweep_exits` + `negative_retry_sweeps` + 센티널 4자리 + LOOSE settle + 반사실 쌍 |
| 3 | N1(플래그 OFF 는 B0) | `RASBERY_A2_PREV_INNER=carry`. `kArmEnv` 51 엔트리 |

**설계서로 되돌려 보내는 정정 2건**

1. **§1.4(a) 의 "≥1,928 outers(≥42 %)" 는 상한의 2배다.** 센티널은 Xe 스텝당 **1 아우터**를
   몰수하지, 2 아우터의 바닥 전체를 만들지 않는다. 스텝을 실은 아우터는 센티널이 없어도
   존재한다. 정정된 상한은 ~964 아우터(**~22 %**)이고, 실제치는 그것의 `hit_rate` 배다.
2. **§3.1 S0 의 `cmfd_sweep_exits` 는 프로덕션 arm 에서 완전히는 분리되지 않는다.**
   디바이스 세그먼트의 verdict 커널이 세그먼트 전체를 accumulator 하나로 접고 `state` 는
   **마지막 launch 의 것만** 남기므로(`src/CudaBICGBackend.cu` 의 `kAccState`), 중간 drive 들의
   종료 사유는 호스트에 도달하지 않는다. 영수증은 그것을 `exit_deferred` 로 **분리 공표**하고
   `exit_attributed_frac` 로 분모를 밝힌다. **S3 의 K0 게이트는 대리 지표
   `deferred_sweeps_per_drive` 로 읽는다 — 값이 `sweep_budget`(=5)에 붙어 있으면 예산 소진이다.**
   완전 분리는 `CmfdSweepProbeSink::Accum` 에 double 2개짜리 히스토그램을 넣는
   **후속 `.cu` 커밋**이며, S0 의 "`.cu` 를 열지 않는다" 규칙 밖이다.

**읽는 순서.**
1. `cmfd.exit_attributed_frac` — 낮으면 `budget_exhausted_frac` 을 인용하지 말고
   `deferred_sweeps_per_drive` 로 읽는다. **S3 의 K0.**
2. `counterfactual.probe_coverage` — 0.9 미만이면 `hit_rate` 를 인용하지 않는다.
3. `counterfactual.loose_hit_rate` — **S4 의 킬 기준 0.30.**
4. `cascade.residual` — 0 이 아니면 §1.3 재귀속 전부 무효.
5. `outers_by_phase.xe / outers` (m64) — **50 % 미만이면 설계서 §1 전제가 m64 로 이전되지
   않는다. 설계 전면 재조준(설계서 S0 킬 기준).**
6. `cmfd.negative_retry_sweeps / cmfd.sweeps` — 15 % 초과면 `_epsl2` 완화보다 먼저 고칠 것.

**중단 신호(설계서 §4.2).** `flux_limit_retries ≠ 0`,
`staged_relapses > 0.2 × search.trials`, `cmfd.sweeps_per_outer > 4.4`.
